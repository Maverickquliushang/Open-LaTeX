# 开发、部署与回滚

每个 PowerShell 进程先加载根目录 `project-env.ps1`。它转调 `code/project-env.ps1`，只设置当前进程与子进程的临时目录及可配置缓存，不更改用户全局环境、HOME 或凭据。所有路径从入口位置解析，支持空格和中文。

独立测试：

```powershell
. ./project-env.ps1
./code/scripts/test.ps1 -BuildImage
```

测试容器默认 `open-latex-dev-validation`。已有同名容器必须带本项目测试标签，并与本项目的两项挂载完全一致；脚本拒绝复用其他资源。测试使用真实 latexmk、BibTeX、Git 等工具，日志留在本地临时目录。项目不会自动删除旧环境或其他 Docker 资源。

部署按文件清单进行，先建立目标基线，再构建并检查产物，然后生成部署计划。执行时再次比对目标与基线、检查运行中的相关操作、备份即将替换的文件，记录每个文件的状态。发生冲突时保留双方并停止；禁止整目录双向同步。

常规清单不包含 `papers/`、任何论文 `.git`、个人日志、编译成品和旧备份。设置更新采用按键合并，未知个人键保留。私人论文修复使用独立备份与清单；只允许已经核实的最小补丁，不将其纳入公开包。

回滚必须指定本轮部署清单，并验证目标仍为本轮部署后哈希；后续用户修改不能被覆盖。回滚只还原清单中的文件，不恢复论文或 Git 历史。

`code/VERSION` 是产品版本唯一来源，扩展在自己的 `package.json` 中管理组件版本。完成新一轮验证后才归档；`versions/v版本/` 已存在时归档脚本拒绝覆盖。源码包采用明确包含目录，排除私人配置、缓存、临时材料、依赖、Git 与历史包。

实际命令和本次结果见项目 README、版本说明及本地私人交接记录。运行包可部署到另一个独立实例，但依赖已经安装的 Docker Desktop、Linux 容器、VS Code 及相应扩展；不是离线 TeX 安装器。
